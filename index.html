01 · esptool manuelESP32

  1. step 01Télécharger le firmware

    Le .bin combiné (bootloader + partitions + app), ou laisse le navigateur le faire via Web Flash.

  2. step 02Installer esptool

    pip install esptool — ou apt install esptool. Source : github.com/espressif/esptool

  3. step 03Donner l'accès au port

    sudo usermod -aG dialout $USER puis reconnexion. Sinon sudo devant la commande.

  4. step 04Identifier le port

    ls /dev/tty{USB,ACM}{0..9} ou dmesg | tail après branchement.

  5. step 05Flasher

    Copie la commande générée ci-dessous, garde le bouton BOOT enfoncé si le port n'est pas détecté.

port série 
# erase then write combined image at 0x0
$ esptool.py --chip esp32 -p /dev/ttyUSB0 -b 460800 --before default_reset --after hard_reset write_flash 0x0 EvilFoX2-0-0.bin
le fichier .bin doit être dans le dossier courant
!

Image "combined" : flash à l'offset 0x0 uniquement. Si tu passes par des fichiers séparés (bootloader.bin, partitions.bin, app.bin), utilise les offsets 0x1000 / 0x8000 / 0x10000.

Un -z 0x0 (déflate) ne fonctionne qu'avec une image compressée ; ici on écrit le binaire brut, plus fiable.

checklistavant de flasher
  • Câble data (pas un cable de charge seul)
  • Pas de hub USB non alimenté
  • Driver CP210x / CH340 installé si pas de /dev/ttyUSBx
  • GitHub ouvert en HTTPS, sinon l'API Serial est bloquée
  • Batteries M5 retirées pendant l'écriture
  • Backup du firmware d'origine si besoin

note

Web Flash (1er onglet) et CLI font la même chose : le navigateur parle directement à l'ESP via Web Serial. Aucun serveur intermédiaire, rien n'est téléversé.

    02 · dépannagefaq

    Le bouton du navigateur reste gris / "no port chosen"
    Chrome, Edge ou Opera de bureau (Web Serial n'existe pas sur Firefox/Safari/Android). Ouvre la page en https:// ou http://localhost. GitHub Pages : vérifie "Enforce HTTPS".
    "Failed to connect to ESP32: No serial data received"
    Maintiens BOOT/GPIO0 (ESP32) ou le bouton G0 (M5) enfoncé jusqu'à ce que le handshake démarre, puis relâche. Essaie un autre port à 115200 en retirant -b 460800.
    "Could not open COM3, the port is busy"
    Ferme ESPHome / Arduino IDE / PuTTY / moniteur série, puis débranche-rebranche. Sous Linux : vérifie dialout ou uucp dans groups.
    Le M5 reste noir après le flash
    Éteins-le (appui long PWR), rallume, et vérifie que tu as flashé le build M5 et non le build ESP32 : le Pin Mapping (écran 1.14", A/B/C) est différent.
    Revenir au firmware d'usine
    Re-flashe une image ESPHome/Home Assistant ou la dernière release EvilFoX avec la même commande, offset 0x0 pour une image combinée.
